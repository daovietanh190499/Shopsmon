Processing pipeline


Six steps, all running as JavaScript and WebAssembly on your device.


    

  1. Image clean-upEXIF orientation, size cap, division by an estimated paper background to remove shadows, contrast stretch.
    2. 

  2. DeskewSkew measured with a projection profile (±10°), then the text lines are rotated level.
    3. 

  3. Find text linesPhoto mode uses PaddleOCR (PP-OCRv6 detection) in a Web Worker to get every text line at any angle.
    4. 

  4. Read the textTesseract.js (LSTM, tessdata_best "vie") reads every tone mark and diacritic; several workers run in parallel.
    5. 

  5. Rebuild layoutFrom text boxes to rows, columns (vertical gutters), tables (aligned cells), lists, headings and paragraphs.
    6. 

  6. ExportText, Markdown, JSON with boxes and confidence, CSV for tables; low-confidence words are flagged.
    7.

Known limits


  • This is classic OCR, not a vision-language model: it does not understand charts, complex merged cells or tables without clear gaps.
    • 

  • Handwriting, curved text, very small text (under about 12 px tall) and blurry images give poor results.
    • 

  • Upside-down or sideways images: use the Rotate buttons first.
    • 

  • Weak devices can be slow in photo mode (a few seconds to tens of seconds per image).





Privacy and requirements


    

  • Images are processed entirely in the browser; no image or text is uploaded to a Shopsmon server.
    • 

  • Libraries (Tesseract.js, PaddleOCR.js) and language data load from the jsDelivr CDN; the text-detection model loads from shopsmon.com.
    • 

  • Requires a browser with WebAssembly and Web Workers (recent Chrome, Edge, Firefox or Safari).
