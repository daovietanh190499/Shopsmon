Send-on-delta: how many sensor messages it saves and what it costs in error

Many IoT platforms send a sensor's new value only when it differs from the last value sent by more than a threshold, instead of sending at a fixed period. This post derives the message rate and the reconstruction error of that rule on two kinds of signal (white noise around a constant, and a noiseless random walk), compares it with periodic sampling at the same number of messages, and then measures it on a signal with measurement noise, where the result is not what intuition suggests. Every number is output of a script with a fixed seed.

1. Background

The OPC UA DataChangeFilter has a deadband option: when a variable is monitored, the server reports a new value only if \(|\text{last cached value} - \text{current value}| > \text{AbsoluteDeadband}\), where the last cached value is the last value that was put in the queue (OPC 10000-4, section 7.22.2). PercentDeadband uses a percentage of the variable's EURange (OPC 10000-8, section 7.2). The specification describes the purpose of the deadband as keeping a noisy signal from updating the client unnecessarily (OPC 10000-4, section 3.1.2). The OPC UA connector in Azure IoT Operations 2610 also has an option to ignore values that barely change, according to Microsoft's post of 17 November 2026 (related news).

In the event-based sampling literature this rule is called send-on-delta (Miskowicz, 2006): the sender keeps the last value it sent (the reference) and sends a new sample only when it differs from the reference by more than \(\delta\). The receiver holds the last received value (zero-order hold, ZOH). Åström and Bernhardsson (2002) studied periodic versus event-based sampling for first-order stochastic systems. This post does not repeat that paper: it derives two simple formulas, checks them by simulation, and adds a measurement of the case with measurement noise.

2. Model and metrics

The sensor is sampled every tick. The sender transmits the first sample, then transmits sample \(x_t\) whenever \(|x_t - r| > \delta\) (strict inequality, as in OPC UA), where \(r\) is the last transmitted sample; after a transmission, \(r \leftarrow x_t\). The receiver reconstructs the signal with ZOH. Three quantities are measured: messages per sample (the message rate), the root-mean-square error (RMSE) and the maximum absolute error between the reconstructed and the true signal, evaluated at every tick.

3. Two formulas

A constant signal in white noise \(N(0,\sigma^2)\). If the reference were one fixed noise sample \(n_r\) and the new sample independent, the difference \(n_t-n_r\sim N(0,2\sigma^2)\) and the probability of exceeding the threshold is

$$P_\text{naive}=2\Bigl(1-\Phi\bigl(\tfrac{\delta}{\sigma\sqrt2}\bigr)\Bigr).$$

This formula ignores that the reference is the very sample that exceeded the threshold, so it is not an arbitrary noise sample. The exact calculation: the reference offset \(a\) (the noise of the last sent sample) is a Markov chain over transmissions; with \(P_a=P(|n-a|>\delta)\), the next sent sample has density \(\varphi(a')\,\mathbf 1[|a'-a|>\delta]/P_a\) and a cycle lasts \(1/P_a\) ticks on average. With \(\pi\) the stationary distribution of the chain, the message rate is \(1/E_\pi[1/P_a]\). The script computes \(\pi\) by power iteration on a grid of 1801 points.

A noiseless random walk. With \(x_t=x_{t-1}+w_t\), \(w_t\sim N(0,\sigma_w^2)\), take the continuous limit (Brownian motion with variance \(\sigma_w^2\) per tick). The exit time from \((-\delta,\delta)\) has expectation \(E[\tau]=\delta^2/\sigma_w^2\), so the message rate is

$$\frac{1}{E[\tau]}=\frac{\sigma_w^2}{\delta^2}.$$

The ZOH error is \(e=x-r\). The function \(u(x)=E_x\!\int_0^\tau B_t^2\,dt\) satisfies \(\tfrac{\sigma_w^2}{2}u''=-x^2\), \(u(\pm\delta)=0\), so \(u(0)=\delta^4/(6\sigma_w^2)\) and the time-averaged squared error is \(u(0)/E[\tau]=\delta^2/6\), that is RMSE \(=\delta/\sqrt6\approx0.408\,\delta\). Periodic sampling with the same number of messages needs a period \(P=\delta^2/\sigma_w^2\) ticks; after \(k\) ticks the error variance is \(k\sigma_w^2\), so the average is \(\sigma_w^2(P-1)/2\approx\delta^2/2\), that is RMSE \(\approx\delta/\sqrt2\). The RMSE ratio is \(\sqrt{1/3}\approx0.577\). In addition, send-on-delta has an absolute error that by construction never exceeds \(\delta\), while the error of periodic sampling is unbounded.

4. Implementation

The full script (four experiments, three figures; about two minutes to run) can be downloaded. The core of the sender and of the receiver:

def sod_indices(x, delta):
    """Indices at which a send-on-delta reporter transmits (the first sample is always sent)."""
    xs = x.tolist()
    ref = xs[0]
    idx = [0]
    for i in range(1, len(xs)):
        v = xs[i]
        if v - ref > delta or ref - v > delta:
            ref = v
            idx.append(i)
    return np.array(idx)

def zoh(n, idx, vals):
    """Receiver reconstruction: hold the last received value."""
    return np.repeat(vals, np.diff(np.append(idx, n)))

5. Setup

Fixed seed 20261122; the script prints identical numbers on every run (it was run twice and the outputs compared). Experiment 1: 10 series of 200,000 samples \(N(0,1)\) each. Experiment 2: 10 random-walk series of 400,000 samples (\(\sigma_w=1\)). Experiment 3: the true signal is a random walk with step standard deviation 0.05 plus noise \(N(0,1)\); the threshold of each method is calibrated by bisection on a separate series of 100,000 samples and then tested on 6 other series of 100,000 samples each. Experiment 4: 10 random-walk series of 400,000 samples with \(\delta=10\). Numbers in parentheses are standard errors across series.

  • The message rate approaches \(\sigma_w^2/\delta^2\) from below: rate \(\times\delta^2\) is 0.58 at \(\delta=2\sigma_w\), then 0.80, 0.89 and 0.95 at \(\delta=20\sigma_w\). The continuous formula is right when \(\delta\) is much larger than a single step; at \(\delta=2\sigma_w\) it overestimates by a factor of about 1.7. The difference is consistent with a discrete-step effect (the random walk jumps across the boundary instead of touching it continuously); this mechanism was not tested separately.
  • RMSE matches the prediction. RMSE/\(\delta\) for send-on-delta is 0.464, 0.444, 0.429, 0.419, decreasing toward \(1/\sqrt6=0.408\). The RMSE ratio against periodic sampling with the same number of messages is 0.536 to 0.576, approaching \(\sqrt{1/3}=0.577\): send-on-delta has a root-mean-square error about 42% to 46% lower.
  • The maximum error is the bigger difference. Send-on-delta never exceeds \(\delta\) (the measured value rounds to \(\delta\) at three decimals); with the same number of messages, periodic sampling has a maximum error of 5.5 times \(\delta\) (\(\delta=2\)), 4.6, 4.1 and 3.6 times (\(\delta=20\)).

8. Experiment 3: a signal with measurement noise

The true signal \(s_t\) is a random walk with step standard deviation 0.05; the sensor returns \(x_t=s_t+n_t\) with \(n_t\sim N(0,1)\). Four methods are given the same message budget: (a) periodic sampling, sending the raw sample; (b) periodic sampling, sending the mean of the block of samples just passed; (c) send-on-delta on the raw sample; (d) send-on-delta on the EWMA-filtered signal \(y_t=y_{t-1}+\alpha(x_t-y_{t-1})\) with \(\alpha=0.1\) (sending the value \(y\)). RMSE is computed against \(s_t\), not against the noisy samples. If every raw sample were sent, the RMSE would be 0.999, and the EWMA signal (with no message limit) has an RMSE of 0.251.

The standard error of each RMSE cell is between 0.001 and 0.018. Because the thresholds were calibrated on a different series, the achieved message counts deviate from the budget: method (c) from −0.4% to +7% (0.0214 instead of 0.0200 at budget 1/50), method (d) from −8% to 0% (0.0046 instead of 0.0050 at 1/200). At the three sparsest budgets (1/200 to 1/50), (c) sends 4% to 7% more than (a) and is still worse; (d) sends less than or equal to the budget and is still better than (b) at all five budgets.

  • Send-on-delta on raw samples is worse than periodic raw sampling: 1.387 versus 1.084 at budget 1/200 (28% higher) and 1.092 versus 1.020 at 1/50. The threshold needed (2.4 to 4.4 times \(\sigma\)) makes every message, by construction, the sample that deviates most from the previous one; the noise is selected rather than averaged out. This explanation is consistent with the measurements, but the mechanism was not isolated by an experiment.
  • Filtering before the threshold test is the main factor. Send-on-delta on EWMA has an RMSE from 0.400 (1/200) down to 0.258 (1/10), which is 38%, 28%, 15%, 10% and 25% lower than the block mean at the five budgets (1/200 to 1/10); at 1/10 it is only 0.007 above the floor of the EWMA filter (0.251).
  • The block mean has an optimum of its own: RMSE falls from 0.641 (block 200) to 0.296 (block 20) and then rises to 0.342 at block 10, because short blocks average out less noise. The EWMA coefficient \(\alpha=0.1\) was kept fixed at every budget, not tuned for each budget.

10. Limitations

  • Only two synthetic signal types: white noise around a constant, and a random walk (with or without measurement noise). The random walk has a constant step standard deviation, so the advantage of send-on-delta here is only the factor 0.577 in RMSE; for a signal that is mostly still and occasionally changes sharply (steps, switching), the saving could be much larger, but this post does not measure it.
  • The measurement noise is independent Gaussian white noise. Autocorrelated noise, heavy-tailed noise or sensor drift would give message rates different from Section 6; these cases were not measured.
  • The EWMA filter uses a fixed \(\alpha=0.1\) and the threshold is calibrated on a series with the same noise level; in practice the noise standard deviation has to be estimated from data. Method (b) sends one block mean per block, so its latency (the value is only available after the block ends) is also not counted in the RMSE.
  • Transmission delay, packet loss and queue behaviour are not in the model; every message is treated as having the same cost (no packet length, energy or QoS). The previous post on MQTT QoS over a lossy link discusses the cost and reliability of a single message.
  • The ZOH simulation measures error at every tick; it does not measure the delay in detecting a sudden change, and EWMA slows the response to a step, which is not measured here.

11. Practical conclusions

  1. Measure the sensor's noise standard deviation before setting a deadband: on a constant signal, \(\delta=\sigma\) still sends 48% of the samples, \(2\sigma\) sends 15.7% and \(3\sigma\) sends 3.4%. A deadband smaller than about \(3\sigma\) mostly fails to filter the noise.
  2. For a noiseless signal, send-on-delta guarantees a reconstruction error no larger than \(\delta\), which periodic sampling does not (its maximum error is 3.6 to 5.5 times \(\delta\) at the same number of messages), and for a random walk it lowers RMSE by about 42% to 46% at the same number of messages.
  3. When the sensor has measurement noise, filter (EWMA or mean) before the threshold test. In the experiment, send-on-delta on raw samples was worse than periodic sending of raw samples, while send-on-delta on the EWMA signal was 10% to 38% better than the block mean in RMSE.
  4. Send a heartbeat if the receiver needs to know the sensor is alive: the longest silence without a heartbeat was about 8.5 times the mean in the simulation, while a heartbeat bounds it at exactly \(H\) at a cost of 13% extra messages at \(H=200\) in this configuration.
