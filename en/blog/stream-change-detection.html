Change detection on a sensor stream: Shewhart, EWMA and CUSUM at equal false-alarm rates

An IoT node that reads temperature, vibration or current every second needs to know when the mean shifts without raising a false alarm every few minutes. This post compares three detectors that run in a few bytes of RAM, tunes the thresholds so all three have the same false-alarm rate, and then measures detection delay, the effect of isolated spikes, correlated noise and integer arithmetic on a microcontroller.

1. Background

A fixed threshold on the raw value (“alarm if the temperature exceeds 80 °C”) only catches large changes. A wearing bearing, a drifting sensor or a weakening pump usually moves the mean by only a fraction of the noise standard deviation — far less than the sample-to-sample scatter. Statistical process control has two classic tools for this situation: Page's cumulative-sum chart CUSUM (1954) and Roberts' exponentially weighted moving average chart EWMA (1959); Lucas and Saccucci (1990) analyse the EWMA in detail. Each needs one or two state variables and a few additions, so they run on microcontrollers without floating-point hardware. This post derives the three detectors (plus a Shewhart chart as the baseline), tunes thresholds by simulation and measures four things: delay versus shift size, the effect of isolated spikes, the effect of autocorrelated noise, and the error introduced by integer arithmetic.

2. Problem and metrics

Samples \(x_t=\mu_t+e_t\) with independent \(e_t\sim N(0,1)\) (already scaled so the noise standard deviation is 1; \(\mu_0=0\) and \(\sigma=1\) are treated as known). The mean is \(\mu_t=0\) before a change and \(\mu_t=\delta\) from sample \(t=1\) onwards in the experiments with a shift. Two standard metrics:

  • ARL\(_0\) (in-control average run length): the mean number of samples to the first alarm when nothing has changed. It is the inverse of the false-alarm rate.
  • ARL\(_1\): the mean number of samples to the first alarm when the mean has shifted by \(\delta\) (detection delay).

A comparison is only fair when all detectors have the same ARL\(_0\); otherwise the one with the lower threshold looks “faster” merely because it raises more false alarms. Here ARL\(_0\)=370.4, exactly that of a Shewhart chart with a 3-sigma limit (\(1/(2(1-\Phi(3)))\)), i.e. about one false alarm per 370 samples.

3. The three detectors

Shewhart. Alarm if \(|x_t|>c\). No state; it looks at one sample.

EWMA (Roberts, 1959): \(z_t=\lambda x_t+(1-\lambda)z_{t-1}\), \(z_0=0\). For white noise of variance 1 the limiting variance of \(z\) is \(\lambda/(2-\lambda)\), so the alarm condition is

$$|z_t|>L\sqrt{\frac{\lambda}{2-\lambda}}.$$

This post uses \(\lambda=1/8\): a power-of-two weight, so the update becomes one bit shift, \(z\mathrel{+}=(x-z)\gg3\), on integers. One state variable.

CUSUM (Page, 1954), two-sided: \(S^+_t=\max(0,\,S^+_{t-1}+x_t-k)\), \(S^-_t=\max(0,\,S^-_{t-1}-x_t-k)\), alarm when \(\max(S^+_t,S^-_t)>h\). The constant \(k\) is the allowance: with \(k=\delta_0/2\) the chart is a sequential likelihood-ratio test for a shift \(\delta_0\); here \(k=0.5\) (designed for a shift of one standard deviation). For a known shift size, Lorden (1971) proved CUSUM is asymptotically optimal and Moustakides (1986) proved it exactly optimal for Lorden's worst-case delay criterion. Two state variables.

Analytic check of the threshold. For one side, Siegmund (1985) approximates the in-control ARL by \((e^{2kb}-2kb-1)/(2k^2)\) with \(b=h+1.166\); the two-sided chart is about half that value. At \(h=4.7963\) (the threshold measured in Section 5) the formula gives 381.5, about 3% from the 370.4 target: simulation and analysis agree.

4. Implementation

The full script (calibration, four experiments, two figures; about 11 minutes) can be downloaded. The core of the two stateful detectors:

LAM, K = 1 / 8, 0.5

def ewma_step(z, x):
    return z + LAM * (x - z)                  # z_t = lam*x_t + (1 - lam)*z_{t-1}

def cusum_step(sp, sm, x):
    return max(0.0, sp + x - K), max(0.0, sm - x - K)

# integer version for a microcontroller (x already scaled by 'scale' and rounded to int32)
z_q += (x_q - z_q) >> 3                         # lambda = 1/8, arithmetic shift = floor division

# 3-point median prefilter (removes an isolated spike completely)
med3 = lambda a, b, c: max(min(a, b), min(max(a, b), c))

State memory: Shewhart 0 variables, EWMA 1, CUSUM 2; the 3-point median filter adds the 2 most recent samples.

5. Experimental setup

Threshold calibration. For each detector, 8,000 white-noise streams of length 4,500 are simulated (fixed seed), the statistic path is computed once (without resetting after an alarm; the first threshold crossing does not depend on that) and the threshold is found by bisection so that the mean ARL\(_0\) equals 370.4. The thresholds found: Shewhart 2.9956 (analytic: 3), EWMA \(L=2.7617\), CUSUM \(h=4.7963\). With the 3-point median prefilter in front (Section 7) the calibration is redone from scratch on the filtered data: 1.9318, 2.7472 and 4.6211.

Validation. ARL\(_0\) re-measured on 20,000 independent streams (different seed): Shewhart 365.9, EWMA 372.0, CUSUM 376.4, each with a standard error of ± 2.6 (the calibration used a smaller sample, so the differences are within the error). Every ARL\(_1\) below is the mean over 20,000 streams with the shift \(\delta\) applied from the first sample and the state initialised at zero (“zero-state”); the standard error of each value follows the ±.

8. Experiment 3: autocorrelated noise

Real sensor noise is rarely white: temperature, voltage and vibration are usually correlated between adjacent samples. Keeping the thresholds calibrated for white noise (no filter) and replacing the noise with an AR(1) process \(e_t=\varphi e_{t-1}+\sqrt{1-\varphi^2}\,\eta_t\) with marginal variance 1, ARL\(_0\) was measured (20,000 streams per cell):

\(\varphi\)ShewhartEWMACUSUM
0 (white noise)362.6 ± 2.6371.4 ± 2.6380.5 ± 2.7
0.3365.2 ± 2.696.6 ± 0.785.9 ± 0.6
0.5385.2 ± 2.752.5 ± 0.347.6 ± 0.3
0.7457.7 ± 3.333.5 ± 0.231.9 ± 0.2
  • EWMA and CUSUM fail quickly. With \(\varphi=0.3\) alone, false alarms arrive after about 90 samples instead of 370 (EWMA 96.6, CUSUM 85.9); at \(\varphi=0.7\), after about 33 samples, roughly 11 times the designed false-alarm rate.
  • Cause for EWMA (derived from a formula and checked with a separate short simulation, not part of the script): for AR(1) noise the variance of \(z\) exceeds the white-noise value \(\lambda/(2-\lambda)\) by the factor \((1+a\varphi)/(1-a\varphi)\), \(a=1-\lambda\). The factor is 1.71 at \(\varphi=0.3\), 2.56 at \(\varphi=0.5\) and 4.16 at \(\varphi=0.7\) (simulation: 1.69, 2.53, 4.08); the standard deviation of \(z\) is 1.31, 1.60 and 2.04 times larger, so a threshold set for white noise is effectively that many times lower.
  • Shewhart does not fail but its ARL\(_0\) grows (457.7 at \(\varphi=0.7\)): the per-sample probability of exceeding the limit is unchanged (the marginal distribution is still normal), and the longer wait to the first alarm is consistent with exceedances arriving in clusters; the script does not measure the clusters directly.

9. Experiment 4: integer arithmetic on a microcontroller

EWMA with \(\lambda=1/8\) in integers: \(x\) is rounded to a multiple of \(1/\text{scale}\) standard deviations, then \(z\mathrel{+}=(x-z)\gg3\). A signed right shift is a floor operation, so each step biases \(z\) by \(-7/16\) of the least significant bit (LSB) on average, and the steady state is biased by about \(-3.5\) LSB (derived from \(-(7/16)/\lambda\)). At 1/256 \(\sigma\) the integer version almost coincides with the float version: ARL\(_0\) is off by 0.7%, ARL\(_1\) by 1.9% at \(\delta=1\). Coarser resolutions make ARL\(_0\) collapse (321, 122, then 34): the systematic offset of \(-3.5\) LSB is 0.055 \(\sigma\), 0.22 \(\sigma\) and 0.44 \(\sigma\) at the three coarser settings, against a threshold distance of \(L\sqrt{\lambda/(2-\lambda)}=0.713\sigma\), and ARL\(_1\) also gets worse because \(z\) is pulled toward negative values. The script does not try remedies for this offset (for example adding a correction before the shift, or rounding to nearest instead of flooring).

10. Limitations

  • All data are simulated Gaussian noise with \(\mu_0\) and \(\sigma\) known exactly. On a real device \(\mu_0,\sigma\) must be estimated from an initial segment, and estimation error shifts ARL\(_0\); the experiments do not measure this.
  • Only a step shift in the mean (present from the very first sample) was tried, not slow drift (a ramp), variance changes or heavy-tailed noise. ARL values are means; the distribution is skewed, so medians are lower and some detections are much slower.
  • Experiment 3 only shows that white-noise thresholds fail under correlated noise; it does not try remedies (recalibrating the threshold on measured noise, whitening with an AR model, sub-sampling) or check whether they preserve ARL\(_1\).
  • The spikes in Experiment 2 are of one kind (isolated, fixed amplitude 8\(\sigma\)); adjacent spikes or smaller ones were not tried.
  • The post only measures numerical behaviour in simulation; it does not measure run time, energy or code size on a real microcontroller.

11. Practical conclusions

  1. Comparing detectors only makes sense after ARL\(_0\) is equalised: at one false alarm per 370 samples, EWMA and CUSUM detect a 1-sigma shift after about 10 samples, 4.3–4.5 times faster than a single-sample limit (43 samples).
  2. Use the single-sample limit only when large changes (about 3 standard deviations and up) matter; for small shifts choose EWMA or CUSUM. EWMA is simpler (one variable, one bit shift); CUSUM is slightly ahead for shifts of 2 standard deviations and more.
  3. Put a 3-point median filter in front of the detector if the sensor produces isolated spikes; the measured price is about 1–5 samples of extra delay.
  4. Measure the autocorrelation of the noise on real data before choosing thresholds: for \(\varphi\ge0.3\) the white-noise threshold makes EWMA/CUSUM raise about 4 times (\(\varphi=0.3\)) to more than 11 times (\(\varphi=0.7\)) as many false alarms.
  5. When implementing EWMA in integers, a resolution of 1/256 standard deviation keeps ARL\(_0\) within about 1% of float; at 1/64 ARL\(_0\) drops 14%, at 1/16 about 67%, because the floor in the right shift gives a systematic negative offset.
