PnP and RANSAC: camera pose from 2D–3D matches with wrong matches, implemented from scratch

Once 3D points exist (triangulation, bundle adjustment), a new image has to be located relative to them: given 3D points \(X_i\) and their pixels \(u_i\), find the camera \(R,t\). That is the Perspective-n-Point (PnP) problem. Real feature matching always contains wrong matches, and this post measures what that does: a linear DLT solver, Gauss-Newton refinement and RANSAC implemented in NumPy and tested on synthetic scenes with a known true pose.

1. Background

In the 3D-reconstruction thread of this blog, the essential matrix gives the relative motion between two images, triangulation gives 3D points and bundle adjustment refines everything. Once a 3D point map exists, later images are usually not processed from scratch: features of the new image are matched to the known 3D points and PnP gives the camera pose. Two practical issues decide quality: (1) feature matching always produces some fraction of wrong matches (outliers), and (2) the solver must remain stable when only a few points are used. This post implements a minimal pipeline (DLT, Gauss-Newton, RANSAC), measures each link and says plainly where it falls short.

2. The problem

The camera intrinsics \(K\) are known. A 3D point \(X_i\) (world frame) projects to pixel \(u_i\) with \(\lambda_i\,K^{-1}\tilde u_i = R X_i + t\); with normalised coordinates \(x_i=K^{-1}\tilde u_i=(x_i,y_i,1)^\top\) this reads \(x_i\sim [R\,|\,t]\,\tilde X_i\). The unknowns are \(R\in SO(3)\) and \(t\in\mathbb R^3\): 6 degrees of freedom, and each match gives 2 equations, so in principle 3 matches suffice. With 3 points (the P3P problem) there are up to 4 solutions (Gao et al., 2003), so in practice at least one more point is needed to choose. EPnP (Lepetit et al., 2009) solves for \(n\ge4\) in \(O(n)\) time. This post implements neither P3P nor EPnP and uses DLT instead; the reason and the cost are measured in Sections 7 and 9.

3. Three components

DLT (Direct Linear Transform). Let \(P=[R\,|\,t]\) with rows \(p_1^\top,p_2^\top,p_3^\top\) and \(\tilde X_i\) the homogeneous coordinates. Each match gives two linear equations in the 12 entries of \(P\):

$$x_i\,(p_3^\top\tilde X_i)-p_1^\top\tilde X_i=0,\qquad y_i\,(p_3^\top\tilde X_i)-p_2^\top\tilde X_i=0.$$

With \(n\ge6\) matches there are \(2n\ge12\) equations, and \(P\) (up to scale) is the right singular vector of the smallest singular value (SVD). The left \(3\times3\) block must then be forced into a rotation: SVD \(P_{:,1:3}=U\,\mathrm{diag}(s)\,V^\top\), take \(R=UV^\top\), scale \(s=\mathrm{mean}(s_i)\) and \(t=P_{:,4}/s\) (flip the sign of \(P\) if the determinant is negative). DLT does not use the constraint \(R\in SO(3)\) while solving and does not minimise reprojection error; it provides an initial solution.

Gauss-Newton on reprojection error. Minimise \(\sum_i\|\pi(RX_i+t)-u_i\|^2\) where \(\pi\) is the projection. Update \(R\leftarrow\exp([\omega]_\times)R\), \(t\leftarrow t+\delta t\); with \(X_c=RX+t\) we have \(\delta X_c=-[X_c]_\times\omega+\delta t\), so the Jacobian of one match is \(\partial\pi/\partial X_c\cdot[-[X_c]_\times\,|\,I]\) (a \(2\times6\) matrix). Solve \((J^\top J+\lambda\,\mathrm{diag}(J^\top J))\,\Delta=-J^\top r\) with \(\lambda=10^{-6}\), at most 15–30 iterations.

RANSAC (Fischler and Bolles, 1981). Repeat: draw \(s\) random matches, solve DLT, count matches whose reprojection error is below a threshold \(\tau\) (inliers), keep the hypothesis with most inliers (ties: lower truncated cost), and finally re-estimate from all inliers (DLT then Gauss-Newton, at most 3 rounds). The number of iterations is adaptive: if the inlier ratio is \(w=1-\varepsilon\), the probability that a sample of \(s\) points is entirely clean is \(w^s\), so to have at least one clean sample with probability \(p\) requires

$$N=\left\lceil\frac{\log(1-p)}{\log\bigl(1-(1-\varepsilon)^s\bigr)}\right\rceil.$$

Here \(s=6\) (the minimal sample size for DLT), \(p=0.99\), a cap of 6000 iterations, and \(w\) is taken from the best hypothesis so far. The formula counts clean samples; a clean sample is not necessarily a good model, which Section 7 measures directly. Values of \(N\) for several \(s\) (formula, not measurements):

4. Implementation

The full script (synthetic scene, three solvers, the experiments, two figures; about 15 minutes on one core) can be downloaded. The core of the DLT and the RANSAC loop:

def dlt_pose(X, uv):
    xn = (uv[:, 0] - CX) / F; yn = (uv[:, 1] - CY) / F          # normalised coordinates
    Xh = np.column_stack([X, np.ones(len(X))])
    A = np.zeros((2 * len(X), 12))
    A[0::2, 0:4] = Xh;  A[0::2, 8:12] = -xn[:, None] * Xh      # x (p3.X) - p1.X = 0
    A[1::2, 4:8] = Xh;  A[1::2, 8:12] = -yn[:, None] * Xh      # y (p3.X) - p2.X = 0
    P = np.linalg.svd(A, full_matrices=False)[2][-1].reshape(3, 4)
    if np.linalg.det(P[:, :3]) < 0: P = -P
    U, S, Vt = np.linalg.svd(P[:, :3])
    return U @ Vt, P[:, 3] / S.mean()                           # R in SO(3), t

def ransac(X, uv, tau, rng, p=0.99, s=6, max_iter=6000):
    best_cnt, best_cost, need, it = -1, np.inf, max_iter, 0
    while it < min(need, max_iter):
        it += 1
        idx = rng.choice(len(X), s, replace=False)
        R, t = dlt_pose(X[idx], uv[idx])
        r = residuals(R, t, X, uv)
        cnt, cost = int((r < tau).sum()), float((np.minimum(r, tau) ** 2).sum())
        if cnt > best_cnt or (cnt == best_cnt and cost < best_cost):
            best_cnt, best_cost, best = cnt, cost, (R, t)
            need = n_iter_needed(cnt / len(X), s, p)            # adaptive stopping
    return refine(X, uv, *best, tau)                            # DLT + Gauss-Newton on all inliers

5. Experimental setup

Synthetic scene: 200 3D points, camera \(f=800\) px, principal point \((320,240)\), image \(640\times480\). Each point sits at a random depth \(z\) in \([4,8]\) (scene units) and a uniformly random image position in \([40,600]\times[40,440]\); the camera is rotated by 5–30° about a random axis and its centre is about 0.3 from the origin. Every pixel coordinate gets \(N(0,\sigma^2)\) noise (default \(\sigma=1\) px). Outliers: a fraction \(\varepsilon\) of the matches is replaced by a uniformly random pixel over the whole image (completely wrong matches); the outlier sets are nested through one fixed permutation, so the rows of a table share the same scenes. Everything is seeded. Success means rotation error below 1° and camera-centre error below 0.1 scene units. “Oracle” is DLT + Gauss-Newton on the true matches only (a lower bound RANSAC cannot beat, because it does not know which matches are right). Scenes per row: 60 (30 for the \(\tau\) table).

Checks before trusting anything. Without noise, DLT on 200 points gives rotation error 0 (to numerical precision) and centre error \(5.9\times10^{-16}\); on exactly 6 points the rotation error is still 0. The post's Gauss-Newton and scipy.optimize.least_squares (LM) on the same noisy scene (\(\sigma=1\)) reach the same solution: camera centres differ by \(4.2\times10^{-10}\) and the reprojection RMS is the same, 1.4616 px; the expected RMS at the least-squares solution is \(\sigma\sqrt{2(1-6/400)}\approx1.404\) px, and 1.46 px is a random sample near that value.

  • The sampler is correct: the measured fraction of completely clean 6-point samples matches \((1-\varepsilon)^6\) (for example 0.5316 versus 0.5314 at \(\varepsilon=0.1\)).
  • But the actual iteration count far exceeds \(N\): at \(\varepsilon=0.3\) the formula gives 37 while RANSAC uses 2636.4 on average and some scenes hit the cap of 6000; at \(\varepsilon=0.1\) the formula gives 7 while RANSAC uses 553.5 on average; at \(\varepsilon=0\) the formula gives 1 but the mean is 313.7. The cause was measured separately (section 7 of the script output): with \(\varepsilon=0.3\), \(\sigma=1\) px, a 6-point sample that is completely clean yields a hypothesis that collects a median of 0.0 % of the true inliers within 3 px (p90: 1.4 %), the share of clean samples collecting 90 % or more of the inliers is 0.0 %, and the rotation error of the clean hypothesis has median 2.70° and p90 19.69°. In other words, DLT from exactly 6 points with 1 px noise is badly conditioned: the formula for \(N\) assumes a clean sample gives a good model, which is not true here, and adapting to the best hypothesis so far stretches the iteration count.
  • Most scenes still succeed because over thousands of tries a good clean sample occasionally appears, and the refinement step (DLT + Gauss-Newton on the inliers found) restores accuracy.

9. Experiment 3: coplanar points

When all 200 3D points lie on one plane (fixed depth 6), the 3×4 DLT is degenerate: the system matrix has rank below 11. Measured (\(\varepsilon=0.3\), \(\sigma=1\) px, 60 scenes, cap of 2000 iterations): with coplanar points DLT fails: success 0.0%, median rotation error 174.8°, p90 179.4°, mean iterations 2000 (the cap); with the same parameters and non-coplanar points: success 100.0%, median 0.043°. A planar surface needs its own solver (for example one built on the plane homography, such as IPPE by Collins and Bartoli, 2014); this post neither implements nor tests it.

10. Limitations

  • Everything is synthetic data: exactly known intrinsics, no lens distortion, independent Gaussian noise, outliers that are uniformly random pixels. Real outliers have structure (repeated patterns, matches near the right place but off by tens of pixels) and are harder; they were not tested.
  • The RANSAC solver is a 6-point DLT; Section 7 shows that hypotheses from clean samples are poor, so the iteration count is large and RANSAC fails at 60 % outliers. A minimal solver (P3P) or EPnP, which build more stable hypotheses from 3–5 points, ordered sampling (PROSAC, Chum and Matas, 2005) and the USAC framework (Raguram et al., 2013) were not tried; the post does not compare them and so does not claim how much faster they are.
  • Success is defined as rotation error below 1° and centre error below 0.1 scene units (depth 4–8); other thresholds give other rates. Scenes per row are 60 (30 in the \(\tau\) table), so the percentages carry sampling error of a few percent up to tens of percent in rows with partial failure.
  • Run time and embedded-device performance were not measured; iteration count is the only cost measure.

11. Practical conclusions

  1. Never solve linear PnP directly on unfiltered matches: in this experiment one wrong match out of 200 breaks DLT in most scenes, and Gauss-Newton from that solution does not rescue it.
  2. RANSAC + refinement on the inliers (DLT then Gauss-Newton) reaches error about 1.01 times the oracle at \(\varepsilon=0.3\) with \(\sigma\) from 0.5 to 4.0 px and still succeeds 98.3% at \(\varepsilon=0.5\); at \(\varepsilon=0.6\) (with the cap of 6000 iterations) only 55.0% remain. Condition: a threshold \(\tau\) of about \(3\sigma\) or somewhat wider.
  3. Do not trust the iteration count from \(N=\log(1-p)/\log(1-(1-\varepsilon)^s)\) when the minimal solver is poorly conditioned: measure how many inliers a clean sample collects; here it is close to zero and the actual iteration count exceeds the formula by 20 to 79 times at \(\varepsilon\) from 0.1 to 0.5.
  4. Coplanar 3D points need a dedicated solver; the 3×4 DLT failed in 100 % of the planar scenes in this experiment.
