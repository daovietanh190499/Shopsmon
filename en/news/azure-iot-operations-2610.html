Microsoft releases Azure IoT Operations 2610: GA and preview channels, an Essentials SKU for large fleets, a policy-governed MCP server and an Inference connector for agents at the edge

2026-11-17 · Source: Microsoft

According to a Microsoft post on the Microsoft Community Hub (Nov 17, 2026), Azure IoT Operations 2610 ships on two channels at once for the first time: GA (stable, fully supported, for production) and public preview (everything in GA plus upcoming capabilities, for test and pilot environments). Users choose a channel at deployment through the Azure portal wizard or Azure CLI and upgrade within that channel; switching an existing instance between GA and preview is not supported. The release is part of a set of Physical AI announcements at Microsoft Ignite. Microsoft describes the platform’s role through three functions: understand the operation (asset context, OPC UA, W3C Web of Things), optimise the operation (models and agents running at the edge next to the data) and govern action (turning an agent’s proposal into an authorised, bounded and observable operation). In the GA channel, 2610 adds a new Essentials SKU that runs the core (the edge MQTT broker, Akri connectors and data flows) on single-node clusters at a lower price point, aimed at hundreds or thousands of small sites such as stores, substations and wind turbines; the full-featured offering is now called Standard (needed for OPC UA or multi-node clusters), moving to Essentials requires a new deployment, and ARM64 has been GA since release 2607. Data flow graphs write directly to Azure Data Lake Storage Gen2 (Delta or Parquet), Microsoft Fabric OneLake tables (Delta) and Azure Data Explorer or local storage (Parquet); in 2610, Delta Lake writes use less memory and carry less transaction-log overhead. Also new are an ODBC-based connector for SQL Server (data from MES, quality, batch and historian systems), management actions for HTTP/REST assets, a smarter OPC UA collector (ignoring values that barely change, dropping readings the equipment flags as unreliable, fixed-interval sampling, and full state snapshots after a restart or network drop), WebAssembly modules that call request-response services over MQTT, and authoring data flows in natural language with GitHub Copilot in VS Code. In the preview channel, Azure IoT Operations includes a Model Context Protocol (MCP) server that gives compatible AI agents and assistants authenticated, authorised access to live MQTT telemetry and state store data at the edge: a single endpoint aggregates first-party and third-party MCP tools, customer-controlled authentication and authorisation policies decide which tools each agent can use, and publishing MQTT messages requires Admin permissions; new application lifecycle capabilities let teams deploy and manage agents and MCP servers on the cluster. The Inference connector runs registered predictive machine learning models, served by Foundry Local on the cluster or hosted in Azure Machine Learning, with multiple models running concurrently; large inputs such as high-resolution images are read from files rather than passed through the broker, and results can feed downstream transforms or trigger management actions on connected assets. Microsoft notes that not every supported model runs locally, and models hosted in Azure Machine Learning may require external connectivity (per iottechnews). Preview also adds a WoT Enrich transform that adds context (meaning and units) to asset messages, an edge registry that stores JSON Schemas and Web of Things Thing Models and Thing Descriptions on the cluster, type-based OPC UA discovery, Microsoft Fabric integration, live data in the operations experience, third-party connectors from Azure Marketplace and the Akri Connector Builder (a GitHub Copilot agent plugin that turns protocol specifications into connector code, tests and documentation). Azure IoT Operations is also in public preview in Azure Government (US Gov Virginia) with the 2610 GA feature set; the preview channel is not available there. On real deployments, Microsoft cites Unilever, working with Microsoft, NVIDIA and Accenture, using the platform for a digital twin of a whole factory, and Schneider Electric’s green-hydrogen pilot with H2E Power, where AI agents validated control logic in simulation before deploying it to hardware; the system ran for more than 6,000 hours autonomously and cut the levelised cost of hydrogen by roughly 10% (figures published by Microsoft). Microsoft also says Azure IoT Operations integrates with Rockwell Automation’s FactoryTalk Optix and is part of Schneider Electric’s EcoStruxure Automation Expert.
