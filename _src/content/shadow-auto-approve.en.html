How many trial runs are enough to trust an auto-approver? Zero failures is not zero risk

An auto-approver (an agent that approves code changes, a filter, an automatic rule...) is usually run in observe-only mode first: it flags “would approve” while a human still decides, and a person then labels each case. This post looks at the statistics behind that step: after \(n\) labelled cases and \(k\) wrong approvals, what do the data prove about the wrong-approval rate \(p\)? It compares four upper bounds (Clopper–Pearson, Wilson, Jeffreys, Wald) with exact calculations, works out the number of cases needed, and then simulates, with a fixed seed, the effect of watching the data continuously (peeking). Every number is the output of one script, on simulated data or computed exactly from the binomial distribution.

1. Context

The news item on Anthropic launching Claude Ship (related news) says that Claude Approvals applies an approval policy written by the team and is recommended to run in observe-only mode before branch protection is set to require its green result. This post considers the general problem of any shadow phase: the automation issues \(n\) “would approve” decisions, and a person labels each one as fine or as having a blocking defect. What can be concluded when every label is “fine”, and how long is it necessary to wait?

Two habits easily lead to wrong conclusions. First, reading “0 failures in 30 cases” as “the failure rate is 0”. Second, watching the data every time a new label arrives and declaring “pass” as soon as the upper bound touches the threshold. This post tests both with numbers.

2. Model and upper bounds

Assume the cases are independent with the same wrong-approval rate \(p\) (the share of cases approved by the automation that a person determines to have a blocking defect). The number of wrong approvals is \(X\sim\mathrm{Binomial}(n,p)\). We want a one-sided upper bound \(u(k,n)\) such that \(\Pr[p\le u(X,n)]\ge 1-\alpha\) with \(\alpha=0.05\). Four common choices:

  • Clopper–Pearson (exact): \(u\) solves \(\Pr[X\le k;\,n,u]=\alpha\), equivalently \(u=F^{-1}_{\mathrm{Beta}(k+1,\,n-k)}(1-\alpha)\). It guarantees coverage \(\ge 1-\alpha\) for every \(p\), but is usually conservative because \(X\) is discrete.
  • Wilson: solve \((\hat p-p)^2=z^2p(1-p)/n\) with \(z=\Phi^{-1}(1-\alpha)=1.6449\) and take the larger root: \(u=\dfrac{\hat p+z^2/2n+z\sqrt{\hat p(1-\hat p)/n+z^2/4n^2}}{1+z^2/n}\). For \(k=0\): \(u=z^2/(n+z^2)\).
  • Jeffreys: a quantile of Beta\((k+\tfrac12,\,n-k+\tfrac12)\).
  • Wald: \(u=\hat p+z\sqrt{\hat p(1-\hat p)/n}\), with \(\hat p=k/n\).

For \(k=0\), Clopper–Pearson gives \((1-u)^n=\alpha\), i.e. \(u=1-\alpha^{1/n}\). Since \(\ln(1-u)\approx -u\), we get the approximation \(u\approx -\ln\alpha/n=2.9957/n\approx 3/n\): the “rule of three” (Hanley and Lippman-Hand, 1983). Wald gives \(u=0\) when \(k=0\), i.e. it asserts with certainty that \(p=0\).

A certificate “\(p\le p_0\) at 95 % confidence” is issued when \(u(k,n)\le p_0\). For Clopper–Pearson this is equivalent to \(\Pr[X\le k;\,n,p_0]\le\alpha\), so the minimum number of cases for each \(k\) can be found by binary search on the binomial distribution function:

from scipy.stats import beta, binom

def ub_cp(k, n, a=0.05):                 # one-sided Clopper-Pearson upper bound
    return 1.0 if k >= n else beta.ppf(1 - a, k + 1, n - k)

def min_n(p0, k, a=0.05):                # smallest n with ub_cp(k, n) <= p0
    lo = hi = max(k, 1)
    while binom.cdf(k, hi, p0) > a:
        lo, hi = hi, hi * 2
    while lo < hi:
        mid = (lo + hi) // 2
        if binom.cdf(k, mid, p0) <= a: hi = mid
        else: lo = mid + 1
    return lo

3. Setup

Sections 4 and 5 are exact calculations (not random), with one 400,000-sample Monte-Carlo cross-check (seed 20261124). Section 6 simulates 20,000 runs, each with at most \(N=2000\) labelled cases, using common random numbers across all rates \(p\); the target threshold is \(p_0=2\) %, \(\alpha=0.05\) one-sided. The values of \(p_0\), \(N\) and the number of looks are choices made for this post, not taken from a real process.

For \(k=0\), the number of cases needed is \(\lceil\ln\alpha/\ln(1-p_0)\rceil\) (59, 149, 299, 598, 2,995), close to \(3/p_0\). One wrong approval multiplies the number of cases needed by about 1.58 at every \(p_0\) in the table (473/299, 236/149, 947/598...); two wrong approvals multiply it by 2.10 and five by 3.51 (at \(p_0=1\) %, computed from the table). Proving \(p\le 0.1\) % takes almost 3,000 labelled cases even with no failures at all.

Waiting for few cases also has a high probability of showing a “clean” record even when the automation is not good: \(\Pr[k=0]\) with \(n=100\) is 36.60 % when \(p=1\) %, 13.26 % when \(p=2\) % and 4.76 % when \(p=3\) % (Monte-Carlo check at \(p=1\) %: 36.71 %). In other words, 100 perfectly clean cases are consistent with a wrong-approval rate of 1 %.

The cause for Wald is the zero-failure case: at \(p=1\) %, \(n=100\), the probability of 0 failures is 36.60 %, and then the Wald bound equals 0, so coverage is only 63.40 % (100 − 36.60 = 63.40). For Clopper–Pearson, 100 % coverage in many cells means the bound is too wide rather than too tight: that is the price of the guarantee for every \(p\).

In the coverage-against-\(n\) plot (Figure 1, right), the coverage of Jeffreys and Wald oscillates in a sawtooth pattern with \(n\). At \(p=1\) %, over the 491 values of \(n\) from 20 to 1,000 (step 2), Clopper–Pearson is below 95 % for none of them (lowest 95.02 % at \(n=628\)); Wilson is below 95 % for 14.1 % of the values (lowest 93.24 %); Jeffreys for 43.8 % (lowest 85.48 %); Wald for 100 %. Wald recovers slowly: its local minima are 74.55 % at \(n=266\), 80.91 % at \(n=434\) and 86.47 % at \(n=868\). The Monte-Carlo check at \(p=1\) %, \(n=1{,}000\): 97.13 %, 97.13 %, 93.42 %, 93.42 % (Clopper–Pearson, Wilson, Jeffreys, Wald), matching the exact calculation to within 0.03 percentage points.

6. Experiment 3: watching the data continuously (peeking)

The Clopper–Pearson bound has 95 % coverage for one look at a pre-set \(n\). If one looks after every case and declares “pass” as soon as \(u(k_n,n)\le p_0\), the probability of issuing a wrong certificate is much higher (Armitage, McPherson and Rowe, 1969, computed this for binomial data). Here a certificate at step \(n\) is issued when \(k_n\le K(n)\), where \(K(n)\) is the largest \(k\) with \(\Pr[X\le k;\,n,p_0]\le\alpha\). For \(p_0=2\) %: a certificate can only be issued from \(n=149\) on (when \(k=0\)); \(K(100)\) does not exist, \(K(1000)=12\) and \(K(2000)=29\) (at most 29 wrong approvals in 2,000, i.e. 1.45 %). Four strategies on the same simulated data:

  • One look at \(n=2000\);
  • Look after every case (\(n=1,\dots,2000\)), stop as soon as it passes;
  • 20 looks at \(n=100,200,\dots,2000\), each at level \(\alpha\) (no correction);
  • 20 looks, each at level \(\alpha/20\) (Bonferroni-style correction: \(K(2000)=23\) instead of 29).

Rows from 2 % upward are wrong certificates (the true rate is not below the target). At exactly \(p=p_0=2\) %, one look issues a wrong certificate 4.27 % of the time (exact 4.17 %, within the simulation noise of \(\pm\)0.14 percentage points), meeting the \(\le 5\) % guarantee; looking after every case issues a wrong one 21.73 % of the time, about 4.3 times the guaranteed level; 20 uncorrected looks issue a wrong one 15.15 % of the time. The \(\alpha/20\) correction holds the error at 1.09 % but lowers the ability to certify an automation that really is good: at \(p=1\) % only 82.89 % of runs obtain a certificate within 2,000 cases, against 97.97 % for one look and 99.29 % for continuous looking (this highest figure comes with 21.73 % wrong certificates at \(p=2\) %).

When the automation is good, the wait is much shorter if early stopping is allowed. The median number of cases at the time of certification (among the runs that certify): at \(p=0.25\) % it is 149 (continuous looking) against 500 (20 corrected looks); at 0.5 % it is 236 against 600; at 1 % it is 386 against 1,100, while a single fixed look needs 2,000. So stopping early helps, but is valid only if the stopping rule and the per-look \(\alpha\) are set in advance and corrected.

7. Limitations

  • The cases are assumed independent with the same \(p\). Real changes differ in risk, drift over time, and many are related (same author, same files) and so are not independent; none of this is measured here.
  • \(p\) is measured against human labels, and people also miss defects: an undetected defect counts as “fine”. A certificate speaks only about the rate relative to the labels, not about true quality, and it does not consider the severity of each defect.
  • Shadow mode contains no feedback: once the automation runs for real, authors and reviewers may change their behaviour, so \(p\) then can differ from the \(p\) measured in observe-only mode.
  • Only the one-sided 95 % bound is considered, with one threshold \(p_0=2\) % in the simulation, \(N=2000\) and 20 evenly spaced looks; other look schedules and \(\alpha\)-spending rules (Pocock, O'Brien–Fleming) were not tried, nor were methods valid at any time.
  • All numbers in Section 6 are simulations of 20,000 runs per rate; the standard sampling error is about 0.15 percentage points at 5 % and 0.29 points at 21.7 %.

8. Practical conclusions

  1. Zero failures is not zero risk: after \(n\) clean cases, the 95 % upper bound is about \(3/n\). Certifying \(p\le 1\) % takes 299 labelled cases (2 %: 149; 0.5 %: 598; 0.1 %: 2,995).
  2. Each observed failure increases the number of cases needed: at \(p_0=1\) % it is 473, 628 and 1,049 for \(k=1\), 2 and 5, against 299 for \(k=0\) (1.58, 2.10 and 3.51 times as many).
  3. Do not use the Wald bound for small rates: at \(p=1\) %, \(n=100\) its coverage is only 63.40 %, and after 0 failures it asserts \(p=0\). Clopper–Pearson kept coverage \(\ge 95\) % in every cell tried; Wilson's lowest was 93.98 %.
  4. Fix the sample size or the look schedule in advance and divide \(\alpha\) among the looks. Looking continuously and stopping when the bound touches the threshold issues a wrong certificate 21.73 % of the time at \(p=p_0\) (target 5 %); dividing \(\alpha\) over 20 looks holds it at 1.09 %, at the cost of a lower chance of certifying a good automation (82.89 % against 97.97 % at \(p=1\) %).
  5. Choose \(p_0\) from the cost of one wrong approval before running, then compute the number of cases needed: if that number is larger than the volume of real changes that can be observed, a certificate at that level cannot be reached.
